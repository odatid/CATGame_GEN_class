# CATGame_GEN — 引継ぎプロンプト

**この文書の使い方**：下の ``` で囲まれた部分を**そのまま新しいチャットに貼る**と、CATGame_GEN の開発が始められます。

ただし、貼る前に **【要記入】が4か所**あります（EMSの定義・持ち時間・成果物の到達点・公開先）。
そこだけ先生が埋めてください。**推測で埋めると、演習と食い違うツールができます。**

---

## 貼る前に埋めてほしい4点（私が勝手に決めていないこと）

| # | 項目 | なぜ私が決められないか |
|---|---|---|
| 1 | **EMS の正式な定義**（E・M・S がそれぞれ何を指すか） | 私はこの演習の呼称を知りません。英語から推測すると外します。「目的・手段・制約」との対応も先生の言い方に合わせるべきです |
| 2 | **オープンキャンパスの持ち時間**（分） | 90分か45分かで、画面数と成果物の到達点が変わります |
| 3 | **到達点**（Webプロトで終わるか、Unityまで行くか） | 高校生が来るのか、大学生スタッフが作るのかで変わります |
| 4 | **リポジトリ名・公開URL** | `CATGame_GEN` をどのアカウント配下に置くか決めていません |

以下、**決まっている部分（目的・手段・制約という構造、猫テーマ、グループワーク）は具体的に書き切りました。**

---

```
あなたは「CATGame_GEN」という新しいWebアプリを、ゼロから作る担当です。
私は大学（TID）の教員です。オープンキャンパスで使う演習ツールを作ります。

════════════════════════════════
■ この演習で学生が学ぶこと（ツールの存在理由はここ）
════════════════════════════════
1. ゲームは「目的・手段・制約（ルール）」の構造でできている、と理解する。
2. その構造を自分で埋められるようになる。
3. それをグループで1本のゲーム案にまとめ、猫をテーマにしたゲームとして形にする。

つまりこのツールは「ゲームを作るツール」ではなく、
「目的・手段・制約を、生徒自身の手で埋めさせて、抜けを指摘するツール」です。
案を自動で作って配るのではありません。生徒が書いた3つを、点検して返します。

────────────────────────────────
■ EMS について
────────────────────────────────
EMS は本学の演習で使っているフレームワークです。【2026-11-01 確定】

  E ＝ Ends（目的）
  M ＝ Means（手段）
  S ＝ Structure（構造）… 制約はここに加える刺激。「○○せずに」「○○しながら」等

「目的・手段・制約」との対応: E=目的／M=手段／制約=Sに与える刺激。

────────────────────────────────
■ ツールの背骨
────────────────────────────────
1つのゲーム案を、必ずこの3つに分解して保持する。

  目的（もくてき）… プレイヤーが欲しい状態を1文で。
  手段（しゅだん）… プレイヤーが使える操作は1つだけ（+サブ）。動詞で書く。
  制約（せいやく）… 目的を邪魔するルール。3つまで。時間・回数・空間・物理・情報のどれか。

【このツールの判定（ここが演習の本体）】
  ・手段だけで目的に届く      → あまい（制約が弱い。すぐ飽きる）
  ・制約が強すぎて手段が無力  → むり（理不尽。笑いではなく怒りになる）
  ・10回やって2〜3回は成功する → ちょうどよい（もう一回を押したくなる）

この3判定を、赤・黄・緑で返す。点数は出さない。
理由は「なぜそう判定したか」を1文で添える（生徒が直せるように）。

【制約は必ず「数値」に落とす】
  「時間が短い」ではなく「30秒」。数値になっていない制約は、未記入として扱い、緑にしない。

────────────────────────────────
■ 猫をテーマにする
────────────────────────────────
手段は「猫の行動」から選ばせる。自由記述にしない。
選択肢があれば全員が着手できる。実観察: 生徒の案は想定内に収まる傾向。

猫の行動（採用11種）:
  高い所に登る／箱に入る／狭い所に入る／獲物を狙って待つ／飛びつく／威嚇する／
  夜に動く／日なたぼっこ／爪とぎ／ものをひっくり返す／ものを置いて道を作る

このそれぞれに「そのまま操作になる動詞」を必ず1つ添える。
例：箱に入る → 箱を動かして導く／高い所に登る → 足場を選んで跳ぶ

【猫の表現ルール】
  ・実在の猫の写真は使わない。図形（四角と三角）で描く。
  ・特定のキャラクター・既存ロゴ・実在の人物は使わない。
  ・色は3色まで。柄は「しま」か「まだら」か「単色」（発展形10種あり）。
  ・鳴き声は「にゃー」だけ。歌詞・既存フレーズは使わない。
  ・音は Web Audio で合成する（音源ファイルを読み込まない）。

────────────────────────────────
■ グループワークを前提にする
────────────────────────────────
1. 役割（4人想定。人数は可変）
     しきり役／記録役／てだて役（手段を決める）／しばり役（制約を決める）
   画面の上に「いま誰の番か」を出し、順番に1つずつ決めさせる。

2. 合意の記録
   「全員が選んだ」ではなく、「反対がなかった」ことを残す。
   各質問の下に「この案に反対の人はいますか」のチェックを置き、
   反対があった場合は理由を1行だけ書かせる。

3. 途中で保存できる
   localStorage に保存し、同じURLを開いたら続きから始まるようにする。保存キーは catgame.v1。

────────────────────────────────
■ 現行ツールから継承するもの
────────────────────────────────
別リポジトリの PK//PROTO（ピコ太郎版）の設計思想・実装・検証を引き継ぐ。

【設計思想（絶対に守る）】
1. 生成AIのAPIは使わない。プロンプトは「DBの文章＋ID参照」から決定的に組み立てる。
2. 生徒はWebアプリだけを使う。DBの保守は教員だけがやる。
3. 出力するプロンプトには「EMSを変えるな」という拘束文を必ず入れる。
4. 制約は数値で書く。数値でない制約は未記入として扱う。
5. 演出（気持ちよさ）は必ず入れる。ただし重くしない。

【特に重要な継承：HTML1ファイルで動くこと】
  ・返すのは JavaScript の断片ではなく .html ファイル1つ
  ・1行目が DOCTYPE、最終行が閉じタグ
  ・保存してダブルクリックした瞬間に遊べる（file:// で動く。外部ファイルを1つも読まない）

【特に重要な継承：コードを包む順番】
  音のコードは骨格のループを包み、笑いの層は骨格と音の更新関数を包む。
  生徒が書く関数（updateGame / drawGameObjects）は絶対に包まない。
  包んだあとに同名の関数宣言が来ると、巻き上げで上書きされて演出が消える。

────────────────────────────────
■ 変えるもの（ピコ太郎 → 猫）
────────────────────────────────
  乗せる対象       ：ピコ太郎 → 猫（図形で描く）
  質問の中心       ：好きなゲーム → 猫のどの行動を手段にするか
  制約の作り方     ：目的・手段・制約の3点セットとして明示
  前提             ：1人で使う → グループで使う（役割・合意・途中保存）
  発表の相手       ：オープンキャンパス来場者と保護者
  データの主役     ：猫の行動と制約の型

【そのまま残すもの】
  ・6種の出力（企画書／イメージ1枚／素材シート／Webプロト／Unity／提案書）
  ・決定的に組み立てる方式（乱数なし）
  ・貼るコードを同梱する方式
  ・実ブラウザで数えて検証する文化
  ・版の刻印（HTMLに直接書く。JSで書き換えない）
  ・push は先生がやる

────────────────────────────────
■ 画面構成
────────────────────────────────
  00 はじめる      … EMSの3分レクチャー
  01 ネコのこと    … 得意・苦手・特徴・買う人（候補から3つまで+その他）
  02 ねらい（目的）… 作りたいゲームを決める（カテゴリ別の候補から）
  03 てだて（手段）… 中心アクション+組み立て案3種+サブ
  04 しばり（制約）… おすすめ案から選び、必ず数値を入れる
  05 点検          … ゲーム性チェック4軸+EMS3色。理由を1文。直す場所を指す
  06 ゲーム案      … 1本にまとめる。ここで初めてタイトルが付く
  07 出力          … 6種をコピー
  08 グループ      … 役割・合意・振り返り

【画面の原則】
  ・1画面に1つのことだけ聞く。
  ・「わからない」で先に進める。止めない。
  ・戻れる。途中保存される。同じURLで続きから。
  ・専門用語を使わない。

────────────────────────────────
■ データ構造
────────────────────────────────
  ACTIONS   {id, label, verb, note, variants[3], rates, why}   猫の行動（手段の材料）
  HUMAN_ACTIONS 同上（人操作のとき）
  PURPOSES / PURPOSES_HUMAN  {id, label, goal, rates}          目的の型（カテゴリ別）
  CONSTRAINTS {id, label, tpl, unit, num}                       制約の型（数値必須）
  PACKS 32案                                                    しばりのおすすめ
  PATTERNS 型ごとのレベル構造                                   作り方の型
  GENRE_HINTS                                                    ジャンル誘導
  EMS_JUDGE                                                     3判定の文言
  OUT_TEMPLATES 6種                                             出力の型

IDは英小文字とアンダースコア。既存IDを壊さない。
参照切れ（存在しないIDを指す）は、機械的に検出する。

────────────────────────────────
■ 検証のやり方
────────────────────────────────
  ・目視で「できました」と言わない。実ブラウザで実行して数える。
  ・点数の代わりに、数えた数を報告する。
  ・検証ページを必ず作る。URLで開ける形にして、先生が自分で再実行できるようにする。
  ・判定が FAIL したら、まず「自分の検証ツールが間違っていないか」を疑う。
  ・テンプレートリテラルの罠に注意（バッククォートと ${ を数えて0個を確認）。
  ・HTMLの中にスクリプトの閉じタグを直書きしない。文字列を分割して持つ。

────────────────────────────────
■ 版の刻印と push
────────────────────────────────
  ・ツール上部に「○○な版」と今回の目玉を小さく出す。
  ・版名は HTML に直接書く（JSで書き換えない）。
  ・版名(title・チップ・CT.VERSION)の3点一致を検証ゲートに入れる。
  ・push は先生がやる。エージェントは push しない。
  ・公開URL: https://odatid.github.io/CATGame_GEN/

────────────────────────────────
■ 作業の進め方
────────────────────────────────
STEP 0  先生の記入（EMSほか）を待つ。推測で埋めない。【済み 2026-11-01】
STEP 1  現行 PK//PROTO を読む。【済み: PikoTGame@main】
STEP 2  診断表を出す。【済み: docs/STEP2_診断表.md】
STEP 3  作る。1回の変更は1テーマだけ。データ → 判定 → 画面 → 出力 の順。
STEP 4  検証ページを作って、実ブラウザで数える。
STEP 5  先生に確認を取る。push は先生がやる。

────────────────────────────────
■ 報告のルール
────────────────────────────────
  ・推測で「できました」と言わない。実行して確認した結果だけを報告する。
  ・件数は必ず数えて報告する。
  ・日本語で書く。専門用語は生徒にも分かる言葉に置き換える。
  ・更新したファイルは、名前を全部挙げる。

────────────────────────────────
■ まず最初にやること
────────────────────────────────
AGENTS.md の現在の状態と次のタスク候補を読み、先生に確認してから着手する。

最後に、私が言っていないことで、あなたが決められないことは、
勝手に決めずに質問してください。
```
